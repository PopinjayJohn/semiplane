0047 — A UI plugin renders what the server stamped, and fetches only what is public

The two reference UI plugins, and the two boundaries that make them safe to ship. The dice roller renders the `Resolution` the hub returned and can roll nothing itself; the link preview reads only `http`/`https` URLs whose resolved address is public unicast, refuses every redirect hop on the same terms, and has no handle of any kind on campaign content. Both are declared inert until the pipeline and the composition root wire them.

Context

[0042]({{ “decisions/0042-the-plugin-registry-is-explicit-and-a-ui-plugin-can-only-emit-known-ops/” | relURL }}) built the two registries and stated two gaps on their own types: a page type is unreachable until somebody mounts it, and a render hook is inert until internal/content asks the registry what it holds. It also said what a UI plugin is handed — a Reader and an Emitter, and nothing else — without naming a single plugin that ships.

This record is about the two plugins that do ship, and about what happened when each one’s obvious failure mode was written down first.

§10.6’s roller row is “renders the server’s result”, which is easy to satisfy wrongly. A form, a POST, a dice.Request — the path of least resistance ends with the handler rendering a number, and the number came from somewhere. The only place it can honestly come from is the hub: realtime.Hub.Dispatch resolves an intent against the campaign’s system and returns a Resolution carrying a version. Rendering anything else is a number with no version beside it, which is a roll nobody can audit and nobody can re-derive. But §10.6 also says a UI plugin must be deterministic, and the two rules together look contradictory until you notice the resolution is the third thing: it is not local (the hub stamped it), and it is not non-deterministic (the system’s own seeded source drew it).

§10.6’s preview row is “read-only; the rule data comes from a gameplay module, never from the UI” — and read-only turns out to be the easy half. The hard half is that “the URL a page linked to” is attacker input arriving through Obsidian Sync, and a helper that fetched whatever it was handed would fetch /c/greyhaven/wiki/Vault and hand a private page’s rendered HTML to whoever wrote the link. That is S-8’s access matrix answered by a path that never went through a gate, and it needs no attacker at all: a GM pasting an internal link is enough. The same request against http://169.254.169.254/ is the ordinary SSRF, and one against a name with an A record pointing at 10.0.0.5 is the same request wearing a name.

Decision

The roller renders the Resolution and can roll nothing. dice.Request.Frame() builds a *realtime.ClientIntent with Op: "roll", and the route hands it to realtime.Hub.Dispatch with an actor built by realtime.NewActor from gate-resolved access only. What is rendered is dice.AnswerOutcome(resolution), reduced to the applied frame’s own fields: Seq, Placement, Version, Op, By. There is no dice parser in this package and crypto/rand is nowhere in its import graph — asserted by a test that parses the source rather than by review, because “I did not write a random source” is exactly the claim a later contributor would break without noticing. The system’s mutation payload is not read: a test plants {"last_roll":{"total":413377}} in the frame’s Args and requires that nothing renders it, because S-12.3 and §10.6.1 both say the UI tier transports a system’s opaque payload and never interprets it.

The one number on the page is the version, and the mutation was made by someone else’s code. A refusal is a 200 with the reason rendered, not a 4xx: the reader’s action was understood and answered, and “the Table declined” is a result. ReadRefusal reads both shapes a refusal arrives in — the realtime.ResolutionFor frame and plugin.RejectionError — because ADR 0042’s production resolver reports the latter and a reader that only knew the frame shape would render a fault page for every refusal a real build produces. That is a bug the tests found by construction, not by inspection, and it is why the fixture uses the real plugin.Reject rather than a hand-rolled error.

The preview’s shape policy always applies; its address policy applies unless the caller supplied a transport. checkURL (scheme, host, credentials) runs for every caller, because nothing about it depends on the transport. checkAddress (a typed non-public address, refused before any I/O) and dialPublicOnly (a name that resolves to one, refused on the resolved address) run for New() — which is what cmd/server wires. NewOver(client) gives up both halves of the address policy and exists because a test needs an httptest.Server, which is on 127.0.0.1. The switch is one field, read in one place, and the doc comment says which half a caller lost; a production caller using it has accepted that a link to 169.254.169.254/ would be fetched.

The refusal is on the resolved address, not the URL string, and every redirect hop is re-checked. http://internal/ and http://127.0.0.1/ and a public name resolving to 10.0.0.5 are four spellings of one request and only the last is distinguishable without resolving, so the hook is Transport.DialContext — the only place in net/http where the answer exists. The allowlist is positive: IsGlobalUnicast plus the explicit reserved-space predicates plus 100.64.0.0/10, because a denylist of the addresses somebody has thought of becomes an SSRF the day the next range is reserved. followRedirects re-runs both checks per hop, because a 302 from a public host to the metadata address passes every check that ran before it.

The package holds no handle to campaign content. Unfurler has an *http.Client and two booleans; Preview is three strings, each one the remote page’s own title, og:description and og:image. There is no parameter through which a caller could ask for a path, and a test parses the package’s imports to prove there is no *os.Root — the claim as a type-graph property rather than as a review promise. The refusal carries no URL and no address: a link’s target is author input and a refusal message is a log line, so Class reduces every error to one fixed word. Every refusal answers 204 with no body, and the reason is that a 404 would tell a scanner which private addresses this instance will not reach — S-8’s existence-oracle reasoning applied to the host rather than to a campaign.

The hook is total, and the degradation is the design. A render hook cannot fail — templ.Component has no error return — so a hook that fetched would have to swallow the refusal and render something. Render therefore takes an already-read preview and Hook takes none: the fetch and the render are separate calls, and “the hook is total” and “a refusal is visible” are both true because they are not the same function. Three states, and only the first two have an href: a preview in the payload names its own URL; with no preview and text that is itself an external URL, the anchor points at the text; with neither, the text renders as a <span>, because an <a href=""> is a focus stop that announces a sentence and goes nowhere.

Plugin markup uses the shell’s hand-written classes and no Tailwind utilities. app.css’s @source globs cover components/**, httpapi/** and domain/** — not web/plugins/** — so a utility class in a plugin’s template is a class the stylesheet never sees, and the page renders unstyled while every other gate passes. The plugins therefore compose .stack, .card, .button, .form, .field, .notice, .target and .skip-link from shell.css, and .target is read from ui.TargetClass rather than spelled, because the stylesheet decides what the class means and a second spelling would be a second answer to --target-min.

Every rule has a fixture that fails it, and the fixtures were checked by mutation. Eleven mutations were run: removing dialPublicOnly from the transport fails TestNewBuildsATransportWithTheDialHookInstalled and TestTheDialHookRefusesEveryReservedRange; dropping the CGNAT branch of isPublic fails three tests; dropping resolveImage’s address branch fails TestResolveImageAppliesTheURLPolicy on loopback and the metadata endpoint; deleting either half of ReadRefusal fails TestARefusalIsReadFromEitherShape and four other tests; blanking ui.TargetClass fails the widget audit and the route audit; deleting the hook’s externalLink gate fails TestAPreviewForOneURLIsNeverRenderedBesideAnother; reading a total out of the frame’s Args fails TestTheRenderedResultIsTheHubsFrame; and forging the actor fails TestTheActorCannotBeForgedFromRequestBytes and TestTheRouteAppliesNoRoleListOfItsOwn. Two mutations found real gaps and were fixed: the class check was strings.Contains(attr, "target"), which passes on class="untargeted", and the name audit did not exist.

Consequences

Three seams outside this work item’s paths, and a reader who assumes they are wired will find inert code. RenderHook has no call site: nothing in internal/content asks the registry for a hook, so the link preview’s card appears on no page until the pipeline’s owner wires it. That is ADR 0042’s stated gap, still open, and the hook’s contract is chosen to be safe while inert — the degradation above is what makes registering it early correct rather than premature. Second, internal/httpapi/router.go must call pluginsroutes.Mount inside mountCampaignRoutes, with the patterns derived from the registry rather than written a second time; a route written in both places is a route that can be changed in one of them, which is the stylesheet-import failure in a URL. Third, cmd/server must build Handler.UI, Handler.Hub, Handler.Preview and Handler.Systems — and Systems is the one worth arguing for, because it is what makes the roller display the campaign’s own notation (§10.4) rather than a hardcoded one, and a campaign whose system is missing renders without notation rather than with the wrong notation.

app.css needs one more @source glob for web/plugins/**, and that edit belongs to the integrator. Until it exists, the plugins are correct and unstyled-by-utility, which is a state no gate catches — the same failure mode as the missing stylesheet import, one layer up. The classes in use are all already defined, so the route renders correctly today; the glob is what lets a future plugin use a utility without a page that looks unstyled.

The a11y claim is the work item’s own, and the guard cannot enforce it for a route package that is not listed. A11Y_ROUTE_PKGS is a $(wildcard …) over four named directories, so creating internal/httpapi/plugins/ did not add it — an explicit list plus a wildcard over nothing. The package ships six tests matching A11Y_TESTS (EveryRoute*, SkipLink, Target) with the three negative controls AGENTS.md requires: each audit is run over a fixture built to violate exactly that rule and must report something that mentions the thing it is about; each is run over a document it is satisfied with and must be silent; and each must pass over the route’s three real documents. Adding the package to A11Y_ROUTE_PKGS is a Makefile edit, which is the integrator’s.

Notation is the system’s answer, and its absence is not an error. Handler.Systems is a func(campaignID) rules.System rather than a registry, because the question is per-campaign. dnd5e supplies the grammar; a campaign whose system is not registered renders the roller with no notation and a page that is still correct, because a wrong notation is worse than none.

Two copy decisions are load-bearing and are stated where they are made. The refusal copy says “the Table” and never “the world” or “the session” — the vocabulary audit walks the parsed tree including comments and attribute names, so a retired word in a data- attribute fails the same test as one in prose. And the preview’s image carries referrerpolicy="no-referrer" while the anchor does not: the image is fetched without the reader asking, which would otherwise send a private campaign’s page URL as the Referer, and a reader who follows the link should still send a referrer to a site they chose to visit.

Alternatives considered

Let the roller compute the total. Rejected, and the reason §10.6’s row is a rule at all: a total this process invented has no version beside it, so a disputed roll cannot be reconstructed and a GM cannot tell a recorded roll from a displayed one. The test that plants a total in the frame’s Args and requires it to stay unread is the direct expression of that.

Check the preview’s URL string and skip the dial hook. Rejected: a name is attacker input, internal.example.com is as likely to be a name as an address, and CheckRedirect alone is the classic bypass — a 302 to a private address passes every check that ran before the hop. The cost is stated rather than hidden: a check at the dial cannot refuse a name before it is resolved, so a hostile name still costs one DNS lookup. That is name resolution, not a fetch of the target, and it is the price of not shipping a resolver-based bypass.

Refuse a same-origin link by comparing hosts in the handler. Rejected: the route package would need to know its own externally-visible host, which is behind a reverse proxy in the ordinary self-hosted deployment, and http://localhost:8080 and http://127.0.0.1:8080 are two spellings of one host. Refusing at the dial covers every spelling, and covers the metadata address and the RFC 1918 ranges with the same code.

Render a preview card and hide it when the fetch failed. Rejected: templ.Component cannot fail, so a fetching hook has to swallow the refusal — and swallowing means the page cannot distinguish “this link has no preview” from “this link was refused”, which is precisely the disclosure S-12.3 forbids. Splitting Render from Unfurl means the refusal reaches a log and the reader gets a plain link.

Write the plugins as .templ files in internal/web/components. Rejected: internal/web/components/** is not this work item’s, and a plugin is not a shell primitive — it is compiled in, it renders inside somebody else’s document, and it has no shell document of its own. html/template inside internal/web/plugins/ keeps the plugin’s markup and its claims in one directory, and the templ.Component it returns is the same type the registry holds either way.
