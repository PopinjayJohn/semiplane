Decisions

Architecture decision records: what was chosen, what it forecloses, and what lost.

Every significant decision gets a record. A decision gets a record when a later reader could reasonably have made a different choice and where being wrong would be expensive to undo: a new dependency, a deviation from the [architecture overview]({{ “design/architecture/” | relURL }}), a change to the data model, URL scheme, protocol, or plugin authority, anything touching path confinement, sanitisation, authorisation or secret redaction, and anything that changes the build or the gate.

Records are immutable and numbered. A number is never reused and never changed. A decision that gets reversed does not have its record edited — the record’s status becomes superseded, superseded_by names the replacement, and both remain readable. That is the point: the reason a decision was not made is usually the reason it should not be remade.

Two records here correct the design records

The [architecture overview]({{ “design/architecture/” | relURL }}) and the [UI specification]({{ “design/ui-ux/” | relURL }}) are dated records published verbatim, and editing them would destroy their value as records. Where they are wrong, the correction lives here:

  • 0016 — the overview’s ETag rule is a defect. Two body variants cannot share one validator without a cache serving a GM’s unredacted page to a player.
  • 0017 — and the cache invariant that 0016 protects is why a cross-campaign link may be written but never inlined.
  • 0018 — the overview’s ruleset chain, read literally, would refuse to resume a campaign whose GM merely toggled a house rule.

All three are also listed in the [known staleness]({{ “design/” | relURL }}#known-staleness) note on the design records index.

A fourth was found in phase 3:

  • 0027 — the overview’s pages table lists a front_matter column, and the table does not have one. The file is the source of truth, so a second copy of a block the parser regenerates in a millisecond is a second answer to “what does this page declare”.

Three more were found in phase 5. The first is a conflict within one record — the UI specification stating two things that cannot both hold — and the other two are decisions the record left to the implementation:

  • 0033 — §4.3 persists the collapsed navigation in sp_ui while §6.6 fixes sp_ui to two fields and rules the rest out, and §4.1’s campaign and mode switchers cannot be server-rendered without making the document vary by sp_ui. In both cases the later and more specific rule governs, and both resolutions are recorded rather than picked in a template.
  • 0034 — TV is a [data-ui] mode and never a width band, because a 55-inch television and a 12.9-inch tablet in landscape are indistinguishable to CSS and need opposite layouts. The record’s own accepted failure mode — an unrecognised TV browser shows the laptop layout until someone presses the switcher once — is kept rather than fixed, and the user-agent allowlist stays narrow.
  • 0035 — no Vary header is emitted at all, and the document’s independence from sp_ui is held by asserting the bytes are identical rather than by asserting the header’s absence. The one blocking inline resolver is under a byte budget the build enforces.

The records

  • 0047 — A UI plugin renders what the server stamped, and fetches only what is public
    The two reference UI plugins, and the two boundaries that make them safe to ship. The dice roller renders the `Resolution` the hub returned and can roll nothing itself; the link preview reads only `http`/`https` URLs whose resolved address is public unicast, refuses every redirect hop on the same terms, and has no handle of any kind on campaign content. Both are declared inert until the pipeline and the composition root wire them.
  • 0048 — A house rule is a keyed setting, and 5e's pack merge is not reused
    The house-rule layer is a set of settings identified by `(capability, key)`, resolved first-match-wins by `determinism.Order`'s `(position, module_id)`, with every conflict logged naming both module ids and carrying nothing else. The three data-level capabilities map one-to-one onto the three shapes a change can have, which makes a module's declared `Scope` the bound on its own body. Registration is the only door a definition enters and it is where `determinism.Scope.Admissible` runs, so there is one admissibility check and not two. `dnd5e`'s pack merge is deliberately not shared: it is last-write-wins by construction, unexported on purpose, and speaks YAML.
  • 0051 — OpenCode is the only agent, and its directory is the committed one
    The repo carried two agent configs and one agent's directory, with `.opencode/skills` a symlink into `.kilo/skills` and a `.gitignore` rule holding that symlink out of diffs. Everything an agent reads now lives under `.opencode/`, and `kilo.json` is gone.
  • 0052 — Third-party browser assets are committed, digest-pinned, and served from our own origin
    PixiJS and Datastar are committed under `internal/web/static/vendor/` with a sha256 per file and the upstream archive integrity, `make vendor` re-fetches and verifies, and `make vendor-check` re-hashes the committed bytes with no network at all.
  • 0054 — A campaign sets its brand, and the server renders the stylesheet
    UI §4.12's theme layer: a `theme.yaml` manifest in the content root, `/c/{slug}/theme.css` generated from a closed vocabulary, two contrast floors measured against each theme's own page, and a refusal that keeps the last known-good sheet while a fault answers 500. `theme.brand_invalid` is recorded here as the twenty-fifth signal beyond §13.2, and the six seams this work item cannot wire are named rather than assumed.
  • 0041 — The rules contract returns mutations and carries its own randomness
    `internal/domain/rules` follows §10.3's shape in every place where the record is right, and departs from it in three: `Apply` takes a `context.Context` and a state by value, and `Derive` returns a named `Payload`. `Context` carries a seed and nothing ambient, so `(state, intent, seed) → mutations` is reproducible by construction rather than by discipline.
  • 0042 — The plugin registry is explicit, and a UI plugin can only emit known ops
    `internal/plugin` is an ordered registry of gameplay systems plus the adapter that turns them into the hub's one resolver; `internal/web/plugins` is a second tier whose only authority is an emitter that dispatches as the reader. Registration is a call in the composition root, a kind is inert when nothing registers it, and the four constraints §10.6 puts on a UI plugin are enforced by the shape of what it is handed rather than by a check it has to pass.
  • 0043 — The conformance suite is the only shared code a foreign system needs
    `internal/domain/rules/conformance` is a published suite every `rules.System` must pass, taking a `rules.System` and four explicit seams and nothing else; `internal/domain/systems/notfive` is a complete system sharing nothing with 5e, and three AST audits make that claim falsifiable rather than documented.
  • 0044 — Determinism is enforced by lint because plugins are compiled in
    S-10.4's three rules — no `time.Now`, no map iteration, no direct `crypto/rand` — are one table in `determinism`, and both enforcement mechanisms are derived from it: `forbidigo`'s patterns are computed from the table rather than written in `.golangci.yml`, and `Audit` walks the same table over the parsed and type-checked rule packages. The `maps.Keys` pattern was written, watched fire on the one correct spelling, and removed. `campaign_rule_modules` arrives as migration 0010, with `campaign_id` as `INTEGER` rather than architecture §10.7's `TEXT`.
  • 0045 — The 5e engine is shared mechanics and a data pack
    `internal/domain/systems/dnd5e` is one Go engine plus one `go:embed`ed YAML pack. Every edition difference is a row, a formula, a toggle or the name of a Go hook; exactly two rules are hooks, and a test asserts the list is exactly two so a third is a decision rather than an entry in a map.
  • 0046 — Edition differences are overlay data, not Go
    `internal/domain/systems/dnd5e/overlays` ships 2014 and 2024 as two `go:embed`ed YAML overlays over the engine's base pack. All four edition differences are rows, switches or a label; no third hook was added, and the diff between the two files is machine-checked so it stays reviewable.
  • 0050 — A dispatch names its own actor, and an actor cannot be decoded from bytes
    `Hub.Dispatch` resolves an intent on behalf of an identity rather than a connection, so a UI plugin can dispatch without a socket. The identity is a `realtime.Actor` with unexported fields and a refusing `UnmarshalJSON`, so 'every field is server-derived' is a property of the type rather than a habit of its call sites.
  • 0055 — Two egresses, one hub: the sidebar is HTML and the canvas is structured data
    UI §7.5's resolution table is implemented as one `events.Hub` with two egress representations. The canvas takes structured deltas over `/c/{slug}/ws`; the sidebar takes rendered DOM fragments over `/c/{slug}/events`. The delivery policy splits on one question — does the newer value make the older one untrue, or merely old? — and the region a fragment announces is a field on its type, refused server-side when it disagrees with its target. The stream's gate is the play gate rather than the edit gate, because one URL carries two payloads. Three of §7.5's four prohibitions are code rather than comment, and the fourth — search has no live region — was already held elsewhere. Separately: the vendored Datastar is 1.0.4 from the upstream release rather than the newest *published* npm package, because every pre-1.0.0 build renamed the event this route writes.
  • 0053 — `/play` serves the table and `/ws` upgrades, and a control the protocol cannot honour is rendered disabled with its reason
    The WebSocket upgrade moves to `/c/{slug}/ws` so `/c/{slug}/play` can serve the document architecture §9 always described, and the action bar's End turn and Chat controls render disabled with the reason stated rather than inventing a client-side turn.
  • 0001 — Go 1.27 as the implementation language
    One language, one process, one binary — and what a static toolchain costs.
  • 0002 — The standard library router, not Chi
    net/http ServeMux carries method and pattern routing; Chi carried two advisories.
  • 0023 — Work-item branch names drop the `phase/` prefix
    A branch named `a/b` and a branch named `a/b/c` cannot both exist in git, so work-item branches are `NN-slug/<work-item>` rather than `phase/NN-slug/<work-item>`.
  • 0003 — slog, with no metrics server and no tracing
    Structured logs with a stable event key, plus counters on /readyz. Nothing else.
  • 0004 — One process, and what that forecloses
    Authoritative game state lives in memory. Two instances behind a load balancer will silently diverge.
  • 0005 — modernc.org/sqlite, not mattn/go-sqlite3
    Pure Go, FTS5 compiled in by default, no cgo — and mattn needs both a build tag and a C compiler.
  • 0006 — The content root is the source of truth
    Markdown files in an Obsidian vault are the content. SQLite is a rebuildable index plus live game state.
  • 0007 — FTS5, unicode61, and deliberately not porter
    An external-content FTS5 table over pages, tokenised without stemming, because TTRPG proper nouns stem badly.
  • 0008 — Forward-only migrations
    A shipped migration is never edited. New schema means a new migration, and FTS5 tables are drop-and-recreate.
  • 0009 — Server-authoritative intents
    Clients send intent and never state. The server validates, applies, versions, and broadcasts.
  • 0010 — coder/websocket, not gorilla
    gorilla/websocket carries an advisory for a weak PRNG in its mask key and panics on concurrent writes.
  • 0011 — Plugins are compiled-in, registered explicitly
    No dynamic loading. No init(). Registration happens in the composition root where it can be read.
  • 0012 — Plugin authority is enforced structurally
    A UI plugin can emit operations a gameplay system resolves. It cannot write state, and it does not need to be trusted not to.
  • 0013 — templ, pinned exactly
    Compiled Go templates. Still v0.x, so the version is pinned rather than ranged.
  • 0014 — Datastar for live chrome only
    SSE patches rendered DOM fragments. It never carries content delivery and it never carries the map.
  • 0015 — PixiJS v8, and a deliberately small client
    WebGL for the map. The client surface stays system-agnostic because token and scene are semiplane-owned.
  • 0016 — Salt the ETag with include_secrets
    The design record's ETag rule is a defect. Two body variants cannot share one validator without leaking secrets to players.
  • 0017 — Cross-campaign links never inline
    A wikilink may point into another campaign. Its content is never inlined, because inlining breaks the two-variant render cache.
  • 0018 — ruleset_version fingerprints semantics, not configuration
    House-rule enablement is deliberately excluded from the fingerprint that gates resume, and drift is recoverable.
  • 0019 — Tailwind as a pinned standalone binary, with the manifest hash committed
    The CSS toolchain is a downloaded executable verified against a committed digest of its own release manifest, and `make check` builds CSS and templ before compiling Go.
  • 0021 — A password is stored as PBKDF2 at OWASP's work factor, and carries its own iteration count
    Password hashing is PBKDF2-HMAC-SHA256 at 600,000 iterations with a per-hash salt, encoded so the iteration count travels with the hash.
  • 0022 — `auth_sessions` keys on a hash of the token, because the database is the thing that gets stolen
    The session token lives in exactly two places, a cookie and the response that set it; the database stores only its SHA-256.
  • 0020 — A forwarding header is evidence of nothing until an operator names the proxy
    Client IP resolution trusts no proxy by default, and walks the forwarding chain right to left when one is configured.
  • 0024 — Authorisation is a gate on the route, not a check inside the handler
    The S-8 access matrix is enforced by one middleware that resolves a campaign's tier, and by three named gates routes mount; no handler re-derives it.
  • 0025 — The first account is a command, not an environment variable
    `semiplane admin create` makes the first account, and no configuration value can bootstrap one; a password in the environment is a password in /proc.
  • 0027 — There is no `front_matter` column, and the database index is a cache of the filesystem
    The file is the source of truth; a second copy of a regenerable front-matter block is a second copy that can disagree with the first.
  • 0028 — Rendered output is permission-neutral: raw HTML is never interpreted, and a block-level element loses its text
    goldmark runs without `WithUnsafe()` and bluemonday is an allowlist, so two independent layers stand between a vault and a reader's DOM.
  • 0031 — `body_plain` is derived from the source, never from rendered HTML
    The searchable text is flattened from the file's own bytes, with `[!secret]` callouts excluded in every reveal state, so a search snippet can never carry secret text to a player.
  • 0026 — A cross-campaign wikilink is spelled `[[/campaign/Page]]`, with the leading slash
    A leading slash is what makes the relative reading and the cross-campaign reading of a wikilink mutually exclusive, and ADR 0017 needs that.
  • 0029 — A redactor sees the whole source, and runs before the render
    Redaction happens on the document text, not on a parsed Document and not on rendered HTML, so no buffer downstream of it ever holds a secret.
  • 0033 — Two conflicts in the UI record, resolved and recorded
    Where §4.3 and §6.6 disagree about persisting the collapsed navigation, and where §4.1's switchers meet §3.7's canonical DOM, the later and more specific rule governs — and both outcomes are recorded rather than picked in markup.
  • 0032 — Six signals beyond the architecture record's list
    §13.2 fixes the observability contract and phase 4 adds six names to it, because the alternative was a hole in S-12.3 rather than a smaller surface.
  • 0034 — TV mode is a mode, not a width band
    A television and a tablet in landscape are indistinguishable to CSS, so the distinction is a resolved root attribute rather than a breakpoint, and it lives in its own stylesheet.
  • 0035 — No `Vary: Cookie`, and exactly one blocking inline script
    The document never varies by the theme cookie, so no `Vary` header is emitted, and the only JavaScript on the critical path is one inline resolver in `<head>` under a byte budget.
  • 0036 — `pages.title` is not redacted, and a title may carry secret text
    S-5.11 scopes redaction to `body_plain`, so a front-matter `title:` is indexed verbatim — and a title is the one place a secret is most likely to be written by accident.
  • 0037 — Zero bytes is not a stable size, and the settle budget is the only clock that can tell a blank note from an unwritten one
    S-4.3's two `stat` samples cannot distinguish a page that is empty from a page whose writer has not started yet, because both are `size == 0`. The filter believed the samples and settled an empty page, which is a wrong `pages` row rather than a merely early one.
  • 0038 — The `.target` class is applied by the render pipeline, after the sanitiser
    semiplane adds one attribute to sanitised output rather than removing one, and it is safe because the value is a constant it owns, the element set is fixed, and the pass runs on a tree parsed from bytes the sanitiser already approved.
  • 0039 — The inert `core` system, so phase 7 runs against something real
    Intent resolution belongs to a gameplay `System` in phase 8. Rather than stub it or reorder the phases, phase 7 registers a system that parses and version-checks intents and resolves nothing — and every operation is refused by name.
  • 0040 — A settle is judged by entitlement, not by a clock the test does not own
    Three tests in the settle filter's suite asserted that a continuously written page never settles. That is a claim about the test's own goroutine, not about the filter, and no quiet period is long enough to make it enforceable. The fixture now records when it delivered each event and judges every arrival by whether S-4.3 permitted it.
